# 網頁結構化擷取

把一個雜亂的網頁變成乾淨、欄位固定的 JSON。

## 總原則：只抽取，不創造

**網頁上沒有的東西，一個字都不准補。** 沒寫價格就是 `null`，不是查同類商品的行情；沒寫作者就是 `null`，不是從網域猜出版社；日期只寫得出「三天前」就照實記，不要自己換算成日期再假裝是原文寫的。

抽取結果會被拿去進資料庫、做比價、餵給下游程式。**一個腦補的數字比一個 `null` 危險得多** —— `null` 會被下游發現，腦補的數字不會。

## 三段流程

### 第一段：取素材

先判斷該用哪個工具，這決定你拿不拿得到東西：

| 頁面類型 | 用什麼 | 為什麼 |
|---|---|---|
| 新聞、部落格、文件、維基 | `web_extract` | 內容在初始 HTML 裡，渲染是浪費 |
| 商品列表、搜尋結果、訂位系統 | `web_render` | 內容由 JavaScript 生出來，`web_extract` 只會拿到空殼 |
| 需要圖片 url 或連結 url 當欄位 | `web_render` | 只有它回傳 `images` 與 `links` |
| 不確定 | 先 `web_extract` | 拿到的文字明顯不完整或只有導覽列，再改用 `web_render` |

`web_render` 的成本是 `web_extract` 的數十倍（要開一個真的瀏覽器），**一次最多三個網址**。不要為了保險每次都用它。

`wait_until` 的選擇：預設 `load` 就好。只有頁面明顯是「先出框架、再打 API 補內容」（無限捲動的列表、儀表板）才換 `networkidle`；但有輪詢或線上客服 widget 的頁面用 `networkidle` 會一直等到逾時，遇到就換回 `load`。

### 第二段：推薦 schema 並確認

**看完素材再設計欄位，不要先射箭再畫靶。**

schema 一定切成兩層：

- **`meta_fields`** —— 整頁只有一份的資訊。文章標題、發布時間、作者、麵包屑分類、頁碼總數。
- **`item_fields`** —— 頁面上重複出現的那個東西的欄位。商品的名稱／價格／原價／圖片／連結，景點的名稱／地址／營業時間。

判斷 `item` 是什麼的方法：**看素材裡哪個結構重複了三次以上**。重複的那個就是 item，包住它的就是 meta。如果整頁只有一篇文章、沒有任何重複結構，`item_fields` 就留空，全部放 `meta_fields` —— 不要為了填滿而硬拆。

每個欄位都要給：欄位名（英文 snake_case）、型別（string / number / boolean / array）、一句話說明、以及**從素材裡摘一個實際的值當範例**。範例值是給使用者驗收用的，讓他一眼看出你有沒有認錯欄位。

推薦完就停下來，用 `clarify` 問使用者要增刪哪些欄位。**沒得到確認不要往下抽。** 這一步是整個流程的意義所在 —— 抽錯欄位的成本遠高於多問一句。

### 第三段：抽取

拿確認後的 schema，把素材抽成 JSON：

```json
{
  "meta": { "...": "..." },
  "items": [ { "...": "..." } ]
}
```

規則：

- **缺值填 `null`**，不要填 `""`、`"N/A"`、`"無"`。
- **數字欄位輸出乾淨數字**：`"NT$ 12,800"` → `12800`。貨幣另外開一個 `currency` 欄位放 `"TWD"`。
- **日期統一 ISO 8601**：`2026-08-20`，有時間才加 `T14:30:00`。原文只有「三天前」這種相對時間就填 `null`，另開一個欄位存原字串。
- **url 欄位只能填 `web_render` 回傳的 `images[].url` 或 `links[].url`**。不准自己把相對路徑拼成絕對路徑，不准把縮圖網址改寫成你猜的大圖網址。
- **item 順序照頁面出現順序**，不要自己排序。

抽完在 JSON 後面附一句話說明：抓到幾筆、哪些欄位大量是 `null`、有沒有明顯被截斷。`web_render` 回傳的 `truncated: true` 一定要講，那代表頁面還有內容沒進來。

## 長頁面怎麼處理

素材被截斷時（`truncated: true`），不要假裝沒看到，也不要直接放棄。依序試：

1. 調高 `max_chars` 重抓一次（上限 100000）。
2. 還是不夠就**分段抽取**：先抽前半段的 items，再用更大的 `max_chars` 或換頁參數抓後半，最後把 items 陣列接起來。`meta` 只從第一段取，不要每段都重抽一次 meta 再互相覆蓋。
3. 頁面有分頁（`?page=2`）就一頁一次呼叫，不要試圖一次塞完。

## 常見錯誤

- **把導覽列和頁尾當成 items** —— 頁首選單也會重複，但它不是資料。item 應該有實質欄位（價格、日期、描述），只有名稱和連結的多半是選單。
- **把促銷標語當成商品名** —— 對照 `links[].text` 和頁面文字，商品名通常同時出現在連結文字和內文。
- **跳過確認直接抽** —— 使用者要的欄位常常跟頁面上最顯眼的欄位不一樣。
- **`web_render` 失敗就放棄** —— `failed` 陣列裡有 `逾時` 就換 `wait_until: "load"` 重試一次；有 `拒絕存取內部位址` 是安全機制擋的，換網址不會有用，直接跟使用者說。
